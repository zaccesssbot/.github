# Accessibility

This applies to every repository owned by this account that does not have its own `ACCESSIBILITY.md`. The account automates work on behalf of [@zaccesss](https://github.com/zaccesss), so its repositories follow the owner's shared accessibility statement, linked at the end of this file.

## Documentation

Documentation in a repository owned by this account aims to:

- Use a real heading outline, so screen readers and the page outline can jump between sections.
- Use link text that says where the link goes, never "click here".
- Give images and badges alt text.
- Write diagrams as Mermaid or tables where possible, so their content is text.
- Show code, commands and output as text, never as screenshots.
- Never rely on colour alone: callouts carry a label such as Note, Tip or Warning.
- Use plain language, explaining a term where it first appears.

### Known limitations

The card on [the account's profile page](https://github.com/zaccesssbot) is an image generated from live statistics. It carries alt text and the links above it are text, but the figures inside it have no text equivalent yet.

## Automated changes

Every pull request this account opens and every commit it makes carries a title in plain words saying what it did, so a reviewer using a screen reader knows what to expect before opening the diff. An automated change that arrives without one is a bug: report it on the repository it landed in.

## Forked repositories

A fork owned by this account is an exact copy of its upstream, reset to it every six hours. Its accessibility is the upstream project's, so report a barrier there rather than on the fork.

## Reporting a barrier

If anything in a repository owned by this account is hard to read or use, open an issue on that repository describing what happened and what would have helped. For anything private, use the owner's [contact page](https://isaacadjei.me/contact).

> [!IMPORTANT]
> An accessibility problem is treated as a bug, not a feature request. These are personal projects, so the owner is not always quick, but a barrier goes to the front of the queue.
